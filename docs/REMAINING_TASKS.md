# 需求用户工作台：后续计划

更新：2026-09-10。本表替代旧执行顺序；历史实测结果见 EVIDENCE.md。

## 产品目标

视频是发现评论的入口。核心是围绕用户自己的业务目标，从评论中发现相关需求，整理评论用户、需求原话与来源，辅助人工判断和跟进。产品不限定行业：租房只是用户解释设计目标的例子，不作为默认业务或首个开发场景。搜索关键词不等于需求判断标准；同一批评论可按不同业务目标分析，保留各自结论。不把公开留言等同于营销联系授权，不推断未公开联系方式。

通用流程：设置业务目标与需求条件 → 搜索相关内容 → 自动读取评论及用户 → 识别与筛选需求 → 用户去重与证据整理 → 人工判断和跟进。视频内容、点赞量等作为辅助信息，不作为主页面重点，也不因补视频指标阻塞评论读取。

## 四个板块的批量操作

| 板块 | 必须具备的操作 |
|---|---|
| 累计任务 | 勾选任务、当前页全选、批量导出、批量删除 |
| 已存视频 | 勾选视频、当前页全选、导出视频资料、下载视频文件、批量删除 |
| 去重用户 | 勾选用户、当前页全选、导出用户资料、批量删除；后续增加需求/跟进标记 |
| 已存评论 | 勾选评论、当前页全选、导出评论、批量删除 |

选择入口不是完成标准。必须验收已选计数、真实目标ID、操作结果和刷新后的数据一致性。全选范围明确为当前页展示记录，不能默默选入其他页或隐藏记录；删除保留影响预览和确认。视频下载沿用平台可用入口，无法下载显示原因，不冒充成功。

## 已有基础

搜索后自动读取首批评论已经接通，单视频100条评论和90位去重用户曾实际跑通；更多评论保留下一批入口。账号操作曾在指定对象完成一次关注/私信测试，不代表对其他用户已有授权。统一批量操作已完成：四个板块共享顶部操作栏，视频/用户/评论在选择模式平铺去重记录，每页最多100条；导出、删除及下载请求反馈的隔离测试通过，实际页面核对1个操作栏、100条可选记录，无横向溢出。

## 分工

开发搭档负责通用功能实现、验证、迁移兼容与说明。用户在实际使用时填写业务目标及需求条件，后续可用相关/不相关评论样例校准判断；没有真实业务配置时，不擅自选择行业、城市或启动客户筛选。联系具体对象时另按已有授权流程确认。

## 范围与验收原则

- 先修好统一批量操作，再搭通用需求工作流；本次只更新计划，不把待执行项目记为已完成。
- 租房、商品购买、服务咨询等仅用于说明可配置能力，不分别开发多套行业系统。
- 至少用两个不同业务目标的隔离样例验证配置切换、需求字段和排除条件，不依赖某个行业的固定词汇。
- 需求结论属于基于评论的判断，应显示依据并允许修正；用户昵称、主页等只使用实际可访问并已读取的信息。

## 已实现：搜索方式提示文案

- 先找视频，按需读取评论：先获取视频列表，再选择感兴趣的视频读取评论。出结果更快，方便筛选；需要手动选择，未读取的视频可能有遗漏的需求用户。
- 搜索后，逐个读取评论：获取视频列表后，自动依次读取各视频的评论及用户信息。减少手动操作，但耗时更长；视频越多，等待越久，途中可能因登录验证或页面限制暂停。
- 自动模式覆盖本次找到的视频，每个视频先读取最多100条评论，不代表获取全部评论；更多评论可继续读取。

搜索页默认先找视频；任务详情显示搜索方式。旧任务没有模式记录时，继续搜索沿用原自动评论行为。
