# 本地学习原型设计与执行记录

用途：非商业学习。范围来自用户确认的两天原型需求，常规选择自主完成。

## 复用选择

- MediaCrawler 固定基线：d6f7c5bb906b6dac40ddf343ef9e26438a3de092（2026-08-14）。保留原始代码和 LICENSE。
- 复用 webui 的 Vite/React 构建、Tailwind 主题、Button/Card/Badge/Input、DataPreviewTable、ThemeToggle。
- 沿用 FastAPI/Python，不导入原 crawler 执行链；原链包含隐身脚本、签名与代理功能，和本任务约束不符。
- Playwright 普通可见浏览器读取页面展示的搜索结果与评论。按用户最新范围，每次搜索通过普通滚动收集最多 100 个视频；遇登录/验证/结构不匹配暂停，不请求非公开接口或注入隐身脚本。仅在用户选择某个视频后读取其评论。
- Appium 增加设备成本，首版不采用。队列无需 Redis，单个浏览器执行线程即可。

## 流程与边界

新入口 learning.app:create_app --factory，仅绑定 127.0.0.1。模拟数据、网页数据、导入数据使用独立来源空间。
SQLite 存储任务、视频、评论、用户、动作和日志；用户以来源+稳定 ID 唯一，任务与记录关联。

评论按 100 条一批收集、每页 100 条显示。SQLite comment_pagination 保存视频 ID、累计目标、请求版本与明确到底标记；继续请求必须携带当前版本，事务拒绝重复点击。部分结果、取消或服务中断后保留记录，再继续时跳过已保存内容，补齐当前页。评论按 comment_rank 首次读取顺序排列，浏览旧页不触发采集。工作台保留所选视频任务，任务历史也可以继续读取。

采集只使用公开页面 DOM 与普通滚动、展开按钮；支持按主评论选择读取回复，纯图片等内容仍不支持。主评论没有新增只标记 partial，只有评论列表中评论正文之外的明确结束提示才置 exhausted。回复保留独立批次目标与结束标记：有可识别回复、页面提供收起入口且无更多展开入口、已满足页面初始数量时，才标记此讨论读取完成；加载不确定时保留 partial。每次执行最多 150 秒，遇验证、视频切换、失败暂停；人工请求继续才开始下一次执行。

回复使用 parent_comment_id 关联主评论，kind=reply，与主评论分页计数分开。主评论和回复共享任务 revision，事务拒绝重复或过时请求；旧版本后台写入不能覆盖新版本的分页状态。实际页面的主评论和回复共用 comment-item 标记，通过 replyContainer 区分区域，不能仅凭同名标记把回复混入主评论。普通“回复”发送按钮不在展开入口匹配范围内。

真实大讨论展开后使用“展开更多”按钮，适配器已补上这个精确文案。仍要求节点位于所选讨论的按钮内、不是用户链接或正文。205 条本地回复夹具覆盖带重叠页面的数据去重及 100 / 100 / 5 续读；真实网页已验证 100 / 46 两页，完整性继续以实际结束状态为准。

回复状态另存 `end_state`：`reading` 为读取中，`batch_complete` 为本批完成，`complete` 为确认读完，`unsupported` 为已到页尾但存在未支持内容，`blocked` 为加载受阻或无法确认。`page_end` 与是否全部保存分开；`unsupported_count` 和 `observed_count` 只描述最后一次页面检查，不作为平台总数。判定页尾须无更多展开入口、有收起入口、无外部加载提示且结构稳定；只检查可读文字是否已保存，空正文和未解析回复另计。`unsupported` 保留 partial 和 exhausted=false，但前后端均禁止重复续读；`blocked` 可人工核对后继续。任务早期超时或验证中断也更新回复状态，避免停止后仍显示读取中。导出保留上述字段。

前端在主评论下显示回复组及作者主页，回复每页 100 条，单独继续读取。直接复用既有任务导出接口，不新增下载服务；文件包含累计主评论、回复关系和用户。新版保持旧任务快照，旧版可能混入自动展开回复的主评论记录不会静默删除。

回复读取器版本 2 支持正文为空但包含可见、带方括号名称的表情图片：保存 `content_type=emoji`、`emoji_labels` 和拼接名称，不保存图片资源。文字回复沿用原始 ID 算法，纯表情 ID 增加类型前缀参与哈希，避免与相同名称的字面文字混淆。隐藏图片不计入；缺少名称的图片保留未支持状态。该能力仅补齐纯表情回复，不扩展主评论或混合图文解析。

分页状态记录 `reader_version`。版本 1 的未支持终态允许用户请求补读；请求在事务内占用新版本和 revision，重复点击拒绝。版本 2 仍为 unsupported 的终态继续禁止重复请求。界面给旧任务显示“补读表情回复”，不会自动执行升级读取。

版本 3 增加图片存在标识，以上版本 2 规则为历史记录。主评论和回复共用 `images.py`：只扫描正文内图片或有明确评论图片标记的节点，排除头像、链接、按钮、隐藏图及已知表情节点。纯图片须有可计算标识的 HTTP(S) 图片路径；未知来源不猜测。图片地址去除查询参数后仅在内存中参与 SHA-256，结果保存摘要、数量和 `content_status=image_not_read`，不保存图片地址/字节。图片加载和资源管理由普通页面处理，适配器不额外请求图片。

文字 ID 保持不变，继续读取时可在原文字记录补充图片标识；纯图片使用类型前缀和路径摘要计算本地 ID。页面无稳定原始评论 ID 时，相同作者、同一讨论、相同图片路径会合并，即使查询参数不同。主评论遇明确页尾仍标 exhausted，但有图片占位时任务为 partial；回复页尾有图片占位时为 unsupported、exhausted=false。图片占位数量与未识别行数量分开，避免“已记录占位”被误说成“没有保存任何记录”。100 条批次计入占位记录，浏览和导出均保留图片未读取状态。

版本 1/2 的未支持终态允许用户补读新版图片标识，版本 3 的未支持终态拒绝重复续读。已完成的历史任务不会自动升级重读。真实图片位置需要现场核验；本地夹具覆盖正文内图片和带明确图片标识的正文外结构，不以夹具通过声称抖音所有图片均可识别。

主评论中识别到图片但没有可用路径标识时，单独记录本次 DOM 的 `unidentified_image_count`，不为其编造稳定评论 ID。主评论明确到页尾时依然显示列表结束，但任务保持部分结果并提示标识无法保存。

换关键词验收发现 waterfall 卡片同时承载图文和相关搜索，不能凭数字 ID 构造视频 URL 后即算视频。现在卡片存在时，仅接受首行有可识别时长的卡片，并保存 `duration`、`content_type=video`；按页面卡片顺序排列，不混入全局链接。无卡片时保留旧的明确视频链接读取路径。未知类型跳过，少于 100 条时保留部分结果。标题里包含“图文”不影响正常视频；只有时长标记作为卡片类型的当前证据，平台改版时仍可能需要适配。

读取器版本 4 增加经真实页面截图确认的 `.RDy3JwM0 > img.duf1cdUE` 正文外图片结构，仍由对应 comment-item 限定，不能从推荐区域或其他讨论取图。主评论已实测保存 195 条含图片的记录。版本 1–3 的未支持终态可人工补读新版标识，版本 4 未支持终态不重复提交。批次成功时也在任务说明附带图片未读取数量，避免把“本批记录保存完成”误解为“图片已识别”。
模拟搜索使用固定数据集进行真实关键词过滤，不按任意关键词伪造命中。
导入兼容 MediaCrawler 的扁平 JSON 视频/评论记录，标注“导入”，不宣称实时验证。
关注和私信只提供模拟执行，服务端拒绝真实执行，不存在可启用的发送适配器。
启动时将未完成任务标为需核对；模拟关注按用户去重，消息按用户+内容去重。
前端呈现任务来源、状态、结果、操作记录与简短日志。无凭证输入框。
