# 关注与私信：单对象确认流程

## 当前交付状态

- 已实现：独立页面、测试范围勾选、账号/对象/消息预览、一次性确认、持久化防重复记录、浏览器串行执行、只读结果核对和登录入口。
- 已验证：隔离网页、数据库与界面上的账号切换拦截、一次性确认、防重复执行和错误对象拦截；真实网页已成功识别本人账号，并对用户指定对象完成一次关注，刷新后显示“相互关注”，账本已通过只读核对更新为成功。
- 已实际验证一次私信：向用户指定的同一个对象发送“测试”，刷新会话后核对到本人发送的同文消息，另一个已登录浏览器的同一会话也只读核对到一条对应本人消息；账本为成功，不代表对方已读。这是本次账号/对象的实测，不保证所有账号与后续页面变化都可用。

## 操作步骤

1. 左侧打开“关注与私信”，点击“打开浏览器登录”，在独立抖音浏览器里本人完成登录/验证码。
2. 点击“我已登录，读取本人账号”，从工具浏览器自动填写本人主页或 `@抖音号`；不能将 `/user/self` 当成唯一账号。填写获准测试对象的完整主页链接，也可从用户详情点击“以此用户填写关注／私信预览”带入对象；这些步骤不执行关注或发送。
3. 选择关注或私信；私信填写最多 500 字的纯文本，首尾空白会去掉，并以预览内容为准。
4. 勾选账号和对象属于获准测试范围，再点“核对账号与操作条件”。只导航、核对或打开私信窗口，不点击关注和发送。
5. 核对通过后，页面显示不可变的账号、对象、消息及有效期。再次勾选明确确认，才可点击最终关注/发送按钮。准备阶段的有效期为 5 分钟；最终执行前再次核对页面身份。
6. 如果显示“结果不确定”，只可点击“只核对结果，不重复执行”。消息出现本人发送的对应记录，仅证明页面呈现该消息，不代表接收者已读。

## 暂停与适配范围

真实页核对要求：从导航里的“我/我的”入口核对本人账号。如果导航使用 `/user/self`，在同一浏览器会话打开临时页面读取可见抖音号，随后关闭临时页面；不把 Edge 等其他浏览器的登录状态当成工具浏览器的状态。当前 URL 必须是指定对象主页。用户资料与相邻操作区须唯一匹配；关注只识别该区的关注/回关按钮，不点击推荐用户按钮。“已关注”“互相关注”“相互关注”均会跳过。

私信额外要求：通过聊天顶部实际打开的主页核对接收对象，不仅比较昵称；可识别聊天记录、输入区和发送按钮，且能区分本人发送与接收消息。已有其他草稿不覆盖。点击一次发送后重新加载会话，只有重新读取到本人发送的同文消息才记为成功；无法核实则标为不确定，不重发。页面验证、登录身份不符、布局不识别或发送条件不足时暂停。

适配规则位于 `learning/account_browser.py`。本次实际观察到 `data-e2e=user-info` 的相邻关注按钮、`#imSaasContainerId` 聊天区域及 `messageMessageBoxisFromMe` 本人消息标记。平台以后改变页面时仍可能受阻，需要重新观察适配。仅有本地测试通过不等于真实发送成功。

## 防重复与权限

同一发送账号、对象、操作、消息生成同一持久化记录。检查中、执行中、已有结果和结果不确定时不会重复派发。确认令牌只能消费一次；重启时未完成执行标记为不确定。删除视频、用户等目录记录不会清除账号操作账本。未提供批量关注或群发入口。

该流程使用本人已登录的普通网页，未调用私有签名接口或绕过平台验证。官方小程序私信能力另有申请与授权条件，当前没有冒用官方 OpenAPI 权限。

参考：[抖音官方私信授权状态接口说明](https://developer.open-douyin.com/docs/resource/zh-CN/mini-app/develop/server/reach-marketing/instant-message/private-message/query-authorize-atatus)。
